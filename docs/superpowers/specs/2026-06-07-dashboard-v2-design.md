## 1. 项目概述

### 1.1 目标

构建一个B站热门视频分析大屏，同时满足：
- **数据可视化展示**：视觉冲击力强，适合汇报展示
- **运营分析价值**：可钻取、可联动，支持深度分析

### 1.2 核心需求

| 维度 | 选择 |
|------|------|
| 目标用户 | 数据可视化展示 + 运营分析师 |
| 布局风格 | 中心辐射式（沉浸式画布） |
| 色彩主题 | B站品牌风（粉+蓝） |
| 数据粒度 | 总览 → 分区 → 视频（三层） |
| 交互方式 | 联动高亮 |
| 技术栈 | React + ECharts |

## 3. 交互模型

### 3.1 状态管理

```typescript
interface DashboardState {
  selectedCategory: string | null;  // 选中的分区
  selectedBvid: string | null;      // 选中的视频
  snapshotDate: string | null;      // 选中的日期
}
```

### 3.2 联动规则

**选中分区时：**
- 分区热力图：高亮该分区
- 趋势折线图：只显示该分区的趋势
- 词云：只显示该分区的词云
- 视频列表：只显示该分区的视频
- 雷达图：显示该分区的平均指标
- 词频趋势：只显示该分区的词频趋势

**选中视频时：**
- 底部面板滑出
- 面板内显示：生命周期 + 互动指标 + 词云 + 热门评论

**清除选中时：**
- 恢复全局视图
- 底部面板收起

### 3.3 视觉反馈

- 选中的分区：热力图中高亮，其他图表标题显示"XX分区"
- 未选中状态：显示"全局"视角
- 过渡动画：数据切换时有0.3s的淡入淡出

### 3.4 日期选择

- 日历控件，只显示有数据的日期
- 选择日期后，所有图表重新请求数据
- 默认显示最新日期

## 4. 图表规格

### 4.1 核心KPI横幅

| 指标 | 数据源 | 格式 | 样式 |
|------|--------|------|------|
| 总播放量 | overview.total_views | 1.2亿 | 蓝色大字 |
| 总点赞数 | overview.total_likes | 856万 | 粉色大字 |
| 活跃分区 | overview.partition_count | 18个 | 白色 |
| 今日热点 | overview.hot_title | 标题文本 | 溢出省略 |
| 新增视频 | overview.new_video_count | 12个 | 绿色 |

### 4.2 分区热力图（主入口）

- 类型：ECharts heatmap
- X轴：分区名称（游戏、动画、音乐...）
- Y轴：日期（最近7天）
- 颜色：播放量映射到颜色深浅
- 交互：点击单元格 → selectedCategory
- 样式：B站粉蓝渐变色阶

### 4.3 趋势折线图

- 类型：ECharts line
- X轴：日期
- Y轴：播放量/点赞数
- 系列：选中分区 vs 全局平均
- 交互：hover显示数值
- 样式：平滑曲线，渐变填充

### 4.4 词云

- 类型：ECharts wordCloud
- **三个标签页**：
  - 标题词云：热门视频标题分词
  - 评论词云：热门视频评论分词
  - 弹幕词云：热门视频弹幕分词
- 交互：
  - 点击标签切换数据源
  - 点击词语 → selectedCategory（如果词关联到分区）
  - hover显示词频+来源
- 样式：B站粉蓝随机分配，字号映射词频

### 4.5 视频列表

- 类型：表格
- 列：排名、标题、UP主、分区、播放量、点赞数
- 行数：**全部热门视频**（虚拟滚动优化）
- 交互：点击行 → selectedBvid → 底部面板滑出
- 样式：固定表头，内容区滚动

### 4.6 雷达图

- 类型：ECharts radar
- 维度：点赞率、投币率、收藏率、评论率、分享率
- 数据：选中分区的平均值 vs 全局平均
- 交互：hover显示数值
- 样式：半透明填充

### 4.7 词频趋势图

- 类型：ECharts line
- X轴：日期
- Y轴：词频
- 数据：用户选择的关键词，或TOP N热门词的趋势
- 交互：
  - 默认显示TOP 5热门词的趋势线
  - 可手动输入/选择关键词
  - hover显示具体数值
- 过滤：需要良好的口水词过滤机制（停用词+低频词）
- 样式：多条折线，B站粉蓝色系

### 4.8 视频详情面板（底部滑出）

- 触发：点击视频列表
- 内容：
  - 左上：生命周期折线图（播放量+点赞数趋势）
  - 右上：互动指标雷达图
  - 左下：该视频词云（标题+评论关键词）
  - 右下：热门评论列表
- 关闭：点击X或点击空白区域

## 5. 数据架构

### 5.1 数据规模

| 数据类型 | 每日数据量 | 存储需求 |
|----------|------------|----------|
| 视频详情 | 14分区 × 100 = 1,400条 | ~1MB |
| UP主信息 | 1,400条 | ~0.5MB |
| 评论 | 1,400 × 200 = 28万条 | ~200MB |
| 弹幕 | 1,400 × 3,000 = 420万条 | ~1GB |
| **合计** | **~450万条** | **~1.2GB/天** |

**存储策略：** 答辩前全部保留，不做天数限制

### 5.2 分区定义

B站分区来源于爬虫采集时的分类。常见分区包括：
- 游戏、动画、音乐、舞蹈、科技、生活、美食、鬼畜、时尚、娱乐、影视、知识、资讯、课堂

**数据来源：** video_detail.ndjson中的sub_category字段
**注意：** 当前爬虫数据中sub_category为空，需要在爬虫中补充采集分区信息，或通过API获取

### 5.3 整体流程

```
┌─────────────────────────────────────────────────────────────┐
│                        爬虫层                                │
├─────────────────────────────────────────────────────────────┤
│  每天凌晨：全量采集 14,000 热门视频                          │
│    - 视频详情、UP主信息                                      │
│    - 每视频 200 条热评                                       │
│    - 每视频 3000 条弹幕                                      │
│  每10分钟：增量采集新增视频 + 重试失败的                      │
│  输出：NDJSON文件，按日期目录存储                             │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                     数据湖（HDFS）                           │
├─────────────────────────────────────────────────────────────┤
│  原始数据存储：                                              │
│  /bilibili/raw/video/date=20260607/                          │
│  /bilibili/raw/comment/date=20260607/                        │
│  /bilibili/raw/danmaku/date=20260607/                        │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                     计算层（Spark）                          │
├─────────────────────────────────────────────────────────────┤
│  每天凌晨：运行一次                                          │
│  1. 数据清洗：去重、缺失值处理、格式标准化                   │
│  2. 特征工程：计算互动指标、分词、词频统计                   │
│  3. 聚合计算：分区统计、趋势计算、词云预计算                 │
│  4. 结果写入 Hive/MySQL                                      │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                     数据仓库（Hive）                         │
├─────────────────────────────────────────────────────────────┤
│  分层存储：                                                  │
│  ODS层：原始数据（HDFS）                                     │
│  DWD层：清洗后的明细数据                                     │
│  DWS层：汇总数据                                             │
│  ADS层：应用数据（供API查询）                                │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                     服务层（MySQL）                          │
├─────────────────────────────────────────────────────────────┤
│  ADS层数据同步到MySQL，供后端API查询                         │
│  答辩前全部保留，不做天数限制                                │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                        API层                                 │
├─────────────────────────────────────────────────────────────┤
│  后端API，按日期查询，返回给前端                              │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                        前端层                                │
├─────────────────────────────────────────────────────────────┤
│  大屏展示，联动交互                                          │
└─────────────────────────────────────────────────────────────┘
```

### 5.4 自动化时间线

```
00:00 ─────────────────────────────────────────────────────── 23:59
  │                                                           │
  ▼                                                           │
  [全量采集] ──完成──┐                                        │
                    │                                        │
                    ▼                                        │
              [增量采集开始] ──每10分钟──▶ [21:00停止]        │
                    │                                        │
                    │    ┌────────────────────────────────────┘
                    │    │
                    │    ▼
                    │  [ETL] ──读取前一天数据──▶ [MySQL]
                    │    │
                    │    ▼
                    │  [次日0点后运行]
                    │
                    └──────────────────────────────────────┘
```

**关键规则：**
- 增量采集必须等全量完成才能开始
- 21:00后停止增量，给ETL留时间窗口
- ETL在次日0点后运行，读取的是**前一天**的快照数据
- 例如：6月8日0点运行ETL，读取6月7日的快照

### 5.6 MySQL表结构

**分区策略：** 按snapshot_date分区

**核心表：**

| 表名 | 说明 | 主键 |
|------|------|------|
| hot_video | 视频主表 | (bvid, snapshot_date) |
| video_interaction | 互动指标 | (bvid, snapshot_date) |
| comment_info | 评论 | (comment_id, snapshot_date) |
| danmaku_info | 弹幕 | (danmaku_id, snapshot_date) |
| word_cloud_title | 标题词云 | (bvid, word, snapshot_date) |
| word_cloud_comment | 评论词云 | (bvid, word, snapshot_date) |
| word_cloud_danmaku | 弹幕词云 | (bvid, word, snapshot_date) |

**衍生指标计算：**
- like_rate = like_count / view_count
- coin_rate = coin_count / view_count
- fav_rate = favorite_count / view_count
- reply_rate = reply_count / view_count
- share_rate = share_count / view_count

### 5.7 词云分词方案

**分词工具：** jieba

**停用词过滤：**
- 常见无意义词：哈哈哈、666、来了、好的、可以
- 标点符号、emoji
- 低频词：词频 < 3 的不保留

**存储粒度：** 以视频为单位，按日期存储

### 9.2 采集流程

**全量采集（每天凌晨）：**
1. 获取当前热门视频列表
2. 采集每个视频的详情
3. 采集每个视频的UP主信息
4. 采集每个视频的评论（全量）
5. 采集每个视频的弹幕（全量）
6. 写入NDJSON文件

**增量采集（每10分钟）：**
1. 获取当前热门视频列表
2. 对比已采集的视频，找出新增的
3. 采集新增视频的详情、UP主、评论、弹幕
4. 重试之前失败的采集任务
5. 写入NDJSON文件

### 9.3 错误处理

- 网络错误：自动重试3次，指数退避
- API限流：检测429状态码，等待后重试
- 数据缺失：记录日志，继续采集其他视频
- 文件写入：原子写入，避免数据损坏
